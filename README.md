# necli

**Русский** | [English](README.en.md)

**necli** — терминальный AI-агент с интерактивным TUI и headless-режимом для сценариев CI. Клиент обращается к LLM-провайдерам напрямую по HTTP, поддерживает потоковую выдачу, вызовы инструментов, сохранение сессий, MCP/LSP, фоновую работу, субагентов и нативные движки для `.docx` и `.pptx`.

Проект не хранит ключи API в коде. Рабочее состояние, сессии, конфигурация провайдеров и загруженные файлы по умолчанию располагаются в каталоге `.data/`, который исключён из Git. Для переноса пользовательских данных можно задать переменную окружения `NECLI_HOME`.

## Требования

| Компонент | Требование |
|---|---|
| Python | **3.10+** |
| Менеджер окружения | [uv](https://docs.astral.sh/uv/) |
| Авторизация LLM | Вход через ChatGPT в браузере или API-ключ совместимого провайдера |
| Операционная система | Linux, macOS или Windows; повышение лимита файловых дескрипторов выполняется только на Unix |

## Установка

Установите `uv`, затем создайте синхронизированное окружение из зафиксированного `uv.lock`:

```bash
pip install uv
uv sync
```

Для запуска линтера и тестов установите дополнительную группу разработки:

```bash
uv sync --extra dev
```

После синхронизации CLI доступен как `uv run necli`. Запуск через исходный файл также поддерживается для совместимости: `uv run python src/main.py`.

## Первый запуск

Запустите интерактивный клиент и выберите провайдера. Верхний пункт `/api` — «Войти через ChatGPT» — откроет браузер, примет callback только на `localhost:1455` и будет автоматически обновлять сессию. Каждый новый запуск входа закрывает предыдущий локальный callback перед повторной попыткой. После авторизации верхняя строка превращается в `ChatGPT OAuth` с действиями использования, управления моделями и выхода; отдельная копия ChatGPT в списке провайдеров не показывается. Оставшийся недельный лимит запрашивается в фоне при запуске и после моментального открытия `/api` или `/models`, показывается в обоих меню и в строке над вводом, а после каждого ответа также обновляется в фоне. API-ключи, модели и роутеры настраиваются через встроенные меню `/api` и `/models`; секреты не требуется передавать через аргументы командной строки.

```bash
uv run necli cli
```

Главные параметры интерактивной команды:

| Параметр | Назначение |
|---|---|
| `--api`, `-A` | Временно выбрать провайдера для текущего запуска. |
| `--model`, `-m` | Указать id или отображаемое имя модели. |
| `--workdir`, `-w` | Задать рабочую директорию агента. |
| `--resume`, `-r` | Продолжить сессию по id или его префиксу. |

Если ход агента затянулся дольше минуты, а вы переключились в другое окно, по завершении придёт системное уведомление (Linux — `notify-send`, macOS — `osascript`, Windows — toast). Фокус терминала отслеживается через focus reporting; если терминал его не поддерживает, уведомление всё равно придёт. Переключатель — `/settings` → Interface → «Уведомления на рабочем столе» (при включении приходит пробный тост). В `/settings` → Interface → «Полные блоки» отдельно выбираются блоки инструментов и мыслей, которые раскрываются в compact- и full-режимах; остальные остаются сжатыми.

## Headless и CI

Команда `run` принимает запрос из stdin, выводит результат в stdout и возвращает код завершения. Это подходит для pipe, cron и CI.

```bash
printf 'Сосчитай строки в Python-файлах проекта' \
  | uv run necli run --quiet --allow-all
```

По завершении хода в сокращённом режиме на stderr выводится сводка `✓ Worked 2m ⎿ 5⟳ · 12🛠 · ↑12K ↓4K`, а прогресс инструментов идёт туда же построчно — stdout остаётся чистым под ответ. Для машинной обработки используйте `--json`; для полного отчёта (все ответы модели и вызовы инструментов с аргументами и выводом, каждое событие по одному разу) — `--full-json`. В headless-режиме интерактивные действия, требующие ответа пользователя, не выполняются.

## Данные и безопасность

> **Не добавляйте `.data/` в репозиторий.** В нём могут находиться ключи API, история диалогов, вложения, конфигурация MCP и другие пользовательские данные.

| Путь | Содержимое |
|---|---|
| `.data/config.json` | Основные настройки интерфейса и агентного режима. |
| `.data/apis.json` | Провайдеры, ключи и fallback-роутеры. |
| `.data/chatgpt_auth.json` | OAuth-токены ChatGPT; файл создаётся с правами `0600`. |
| `.data/sessions/` | История и статистика сессий. |
| `.data/memory/` | Долговременная память проекта и глобальная память. |
| `.data/skills/` | Пользовательские и встроенные скиллы. |

Полное описание архитектуры, форматов вызова инструментов, режимов, сессий, MCP, LSP, Telegram-моста и офисных движков находится в [DOCS.md](DOCS.md).

## Разработка

В проекте зафиксированы зависимости, конфигурация тестов и правила статического анализа. Перед отправкой изменений запустите:

```bash
uv sync --extra dev
uv run ruff format --check src tests
uv run ruff check src tests --no-cache
uv run pytest -q
```

Автоматическое форматирование и безопасные исправления линтера:

```bash
uv run ruff format src tests
uv run ruff check src tests --fix
```

## Структура

```text
src/
├── agent/          # цикл агента, потоковая обработка, субагенты
├── apis/           # провайдеры, адаптеры, MCP и LSP
├── commands/       # CLI-команды, slash-команды и меню
├── config/         # настройки, пути, локализация и темы
├── docx_engine/    # создание, изменение и анализ DOCX
├── pptx_engine/    # создание, изменение, анализ и рендер PPTX
├── session/         # хранение сессий и статистики
├── tools/           # файловые, shell, сетевые и офисные инструменты
└── ui/              # prompt_toolkit-интерфейс

tests/              # регрессионные и модульные тесты
```
